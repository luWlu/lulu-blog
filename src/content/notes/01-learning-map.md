> 这是一篇示例文章，用来预览标题、段落、目录和表格的排版。它不代表已经完成的个人学习成果。

## 从一个问题开始

学习记录可以不必一开始就很完整。先写下一个具体问题，再记录为了理解它所做的阅读、推导或实践。

**这一篇想回答的问题：** 如何把零散的硬件知识整理成可以持续扩展的学习地图？

## 给知识留一个位置

可以按「概念 → 关系 → 验证 → 复盘」整理一篇笔记。下面的表格是一份可修改的记录框架。

| 记录部分 | 可以填写什么 |
| --- | --- |
| 问题 | 本次想弄清楚的事情 |
| 概念 | 新接触到的术语与定义 |
| 验证 | 阅读来源、推导或实验记录 |
| 复盘 | 目前的理解与尚未解决的问题 |

### 给每篇笔记一个小结

- 我这次理解了什么？
- 哪个环节仍然不确定？
- 下次应该读什么、试什么？

## 留下下一步

把待解决的问题留在文章结尾，就有了下一篇笔记的起点。

这里可以放你的真实内容、原理图或参考资料。第一篇笔记不必完美，开始记录就已经很好。
