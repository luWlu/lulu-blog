# lulu's blog：技术栈与维护约定

继续使用 **Astro + Markdown 内容集合 + 原生 CSS / JavaScript + GitHub Actions → GitHub Pages**。这套结构适合以技术长文为主、少量交互的个人博客，也保留了日后添加波形图或局部工具的空间。

本文说明技术选择与维护边界。具体写作和发布步骤见 [README](../README.md)；测试是否通过、发布是否完成，应以当前代码对应的检查输出和 Actions 结果为准，不在文档里固定页面数量或长期保留某次构建成功的断言。

## 当前结构

| 层 | 采用方案 | 原因 |
| --- | --- | --- |
| 页面生成 | Astro，静态输出 | 构建后直接托管 HTML / CSS / JS，无需常驻服务器 |
| 内容 | Markdown + Content Collections | 一篇文件对应一篇文章，frontmatter 校验元信息 |
| 样式 | 原生 CSS + 主题变量 | 维护浅色 / 深色模式、响应式与代码配色 |
| 交互 | 少量原生 JavaScript | 搜索、主题切换、目录定位、代码复制等按需要加载 |
| 发布 | GitHub Actions → Pages | 检查、构建、校验产物，再上传静态网站 |
| 版本管理 | Git + 锁定依赖 | 保留修改历史，CI 使用 `npm ci` 复现安装 |

Astro 支持在局部使用 React / Vue / Svelte 等组件，但本博客目前不需要为阅读页面额外引入运行时框架。页面已有搜索、主题和阅读辅助脚本，不能把本站描述成“首页零 JavaScript”。

## 已有阅读功能

- 文章页自动提取二级、三级标题；桌面目录随滚动高亮，手机和平板使用折叠目录。
- 文章阅读进度、双主题代码高亮和代码复制；浏览器限制剪贴板时提示手动选择。
- 本地条目搜索匹配**标题、简介与标签，不搜索正文**；支持 Ctrl / Command + K、`/`、上下键、Enter 和 Esc，按钮提示随平台调整。
- 学习记录分类筛选、移动导航、浅色 / 深色主题与减少动画偏好。
- RSS、sitemap、canonical、文章级 Open Graph / BlogPosting，以及 1200 × 630 PNG 社交分享图。

标签目前用于展示与搜索，**没有独立标签归档页、分页或相关文章推荐**。这些可以在文章数量增长后再考虑，不能把它们列为已实现功能。

## 写作和事实边界

日期按 `Asia/Shanghai` 显示。纯 `YYYY-MM-DD` 表示作者选择的发布日期，带时区的时间戳按北京时间展示；RSS、页面机器可读时间和文章元信息使用标准时间格式。整理旧资料可以使用实际整理发布日期，并在正文说明，不推测实验完成日期。

工具名称使用双引号字符串；有记录的版本才写版本号。EMIO 等文章的工具版本未知时保持为 `Vivado` / `Vitis`，不因为其他工程使用 2020.2 就统一补成同一版本。

理论推算、编译产物、仿真运行和上板实测应分别标注。编译产物中有 PASS 字符串不等于仿真已执行；预期表与测量模板不等于已测得结果。当前实验仍有 UL3 驱动器型号与脚序、C8 电平配置、部分贴片和版图细节待核对，保留适配说明，不通过润色补成确定事实。原有内联示意图可以继续使用，额外图片不是发布的前置条件。

## 发布与校验

GitHub Pages 只托管静态文件，不提供应用服务器或数据库。本站使用 Actions 上传构建产物，仓库 Pages 的 Source 应为 **GitHub Actions**；如果改成分支发布，需另外处理 Jekyll 对下划线目录的规则，例如提供 `.nojekyll`。

发布目标为 [lulu's blog](https://luwlu.github.io/lulu-blog/)。部署配置根据 GitHub 仓库名推导项目子路径；自定义域名时可通过 `SITE_URL`、`BASE_PATH` 显式覆盖，详细步骤见 [README 的部署说明](../README.md#免费部署到-github-pages)。域名、带宽、构建和账户限制可能变化，正式规划以 [GitHub Pages 官方限制](https://docs.github.com/zh/pages/getting-started-with-github-pages/github-pages-limits) 为准。

发布前在项目目录运行：

```powershell
npm test
npm run check
npm run build
npm run verify:build
```

单元检查覆盖内容统计、Markdown 处理与路径解析等逻辑；构建产物校验检查链接、锚点、元信息和收录范围。浏览器中还应核对移动导航、两种主题、搜索键盘操作、目录、代码复制与阅读进度。检查输出只证明对应范围，不能代替板卡实验验证。

草稿在公开页面、搜索、RSS 和 sitemap 中排除；已发布的 `sample: true` 内容有示例标记，详情不索引，且不进入 RSS / sitemap。RSS 最多提供最近 30 条真实内容，搜索索引包含三类已发布条目。

历史预览截图和旧构建产物已归档到项目外，不进入公开仓库。本轮临时预览也由忽略规则排除；日常维护只需提交源代码、内容和锁文件。

## 什么时候考虑替代方案

| 方案 | 适合的变化 | 主要成本 |
| --- | --- | --- |
| Hugo + PaperMod / Blowfish | 希望以现成主题为主、减少自定义交互 | 迁移模板、内容约定和现有界面 |
| Hexo + 中文主题 | 希望采用成熟中文博客主题与插件 | 迁移现有 Astro 组件并维护插件组合 |
| Eleventy | 希望更自由地选择模板与构建步骤 | 阅读功能和主题需自行组织 |
| VitePress / Docusaurus | 内容逐渐以产品文档和层级手册为主 | 重新组织博客与导航结构 |
| Next.js / Nuxt | 已出现明确服务端或复杂应用需求 | 增加运行和部署复杂度，纯静态博客收益有限 |

评论可选 Giscus、Utterances、Waline 等，正文搜索可评估 Pagefind；统计、邮件订阅和 CMS 都应按真实需求单独引入，不默认为已有功能。希望改善中国大陆访问时，先实测，再比较其他静态托管或 CDN；多站点部署还要分别核对 base、canonical 和搜索/RSS 地址，不能直接假定一份路径配置适合所有镜像。
